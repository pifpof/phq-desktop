## Problems found and fixed

- Haiku left out the change report when the tool schema made it optional; a regeneration now uses a variant of the tool where it is required.
- The change report was dropped when the executor fixed up an article's sources, which forced a retry every time.
- The review asked for the job a moment before it was marked ready; it now keeps asking for a few seconds.
- An interrupted regeneration would have resumed after a restart as a normal run, writing straight to the wiki. It is now marked failed instead.
- Outside-edit detection uses a content hash that ignores See Also, because the app edits See Also for reciprocity long after a page is written.

## Decisions to review

- **Partly applied counts as applied** (as REQUIREMENTS-v3.1 5 says). The Kept screen says so and suggests a related change if something is missing.
- **No web refresh with private evidence**, instead of a separate gather and write step: the preview explains it. The page's existing sources are used.
- **Raw files a refreshed web search saves** during a regeneration are deleted on Discard (unless something already cites them).
