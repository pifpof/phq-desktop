## Problems found and fixed

- The value driver articles repeat their title as an H2 under the abstract; assembly only dropped the H1 (Phase 0, `docs/v4.4-heading-bug.md`).
- Step states read run files that hadn't caught up with the run in memory; they now use the live run first.
- Playbook sections listed in task order; they now follow the playbook's order and names.
- A kept regeneration leaves an empty receipt, which hid Open and Regenerate; the page now falls back to the step's page in the article map.
- Two saves of the playbook nav state in one render overwrote each other; saves now apply to the latest state.
- Closing the app with the done screen unseen only toasted on relaunch; it now shows the done screen.
- CI on Ubuntu failed once in `npm test` (not reproducible locally in 6 runs); the test timeout and the pipeline wait were raised for slower machines.

## Deviations

- **Proof dropped during a run waits in app state, not in `inbox/`.** The extract step reads `inbox/`, so a file there could reach the run that is going if extract hadn't run yet. Holding it outside the wiki keeps the run's inputs fixed, as REQ 4.4 intends. "Update the playbook" adds the files as customer references and opens the proof section's regenerate preview.
- **No separate `run:playbookReady` and `run:taskFinished` channels.** The run state carries `kind`, `playbookReadyAt` and `doneSeenAt`, and every run event already reaches the window; the renderer reacts to those. The OS notification click has its own event.
- **"Safe to navigate" is the Research page** with nothing ticked (REQ 3.2 says "Home with nothing open"; the app has no separate Home page). At launch, an unseen done screen always shows.
- **Screen reader detection** for the countdown isn't possible from a web page; the countdown stops under reduced motion and on any key, and isn't announced each second.
- **Time left** uses the longer of the longest remaining chain and all remaining work spread over the concurrency (REQ 4.2's formula divides the chain by the concurrency, which underestimates a chain).
- **The "What you'll get" list is folded into the task list** (REQ 4.4 as updated): the playbook group shows the seven steps with the playbook's names.
- **Source links on finding cards show the domain as text.** The external link allowlist opens a source only from a page that lists it; cards read drafts.
- **Publish the playbook ticked with earlier research steps runs straight away**, because it depends on the sections, not on research. The done screen then comes early. That follows the dependencies; worth a look if it confuses.
